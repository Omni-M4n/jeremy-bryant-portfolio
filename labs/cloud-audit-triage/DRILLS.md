# Practice progression: Build a cloud audit evidence timeline

Use the prepare, show and check commands in [README.md](README.md). Save a prediction before you run `analyse`. Use fresh folders to keep earlier attempts.

1. **Guided (10 minutes):** make a time line with each ID, identity, session, action and result. Add each possible sign-in link. Predict the labels before you open the worked example.
2. **With prompts (5 minutes):** did the action succeed? Do identity and session both match? How many minutes passed? Does the approval name this resource?
3. **Independent (10 minutes):** prepare `challenge` in a fresh folder. Build the time line. Check each possible link against the identity, resource and time rules. Explain any links you cannot prove. Save your answers, evidence and a short handover first. Then open `analyse`, the reference answers or worked example. Record any help used.
4. **Changed evidence (5 minutes):** prepare `changed`. Check every event and the logging decision. In a practice copy, change only `c03.result` to `success`. Predict all results before you check them. Cite the rules for any results that stay the same or change.
5. **Teach back (5 minutes):** explain three different claims. A sign-in worked. An object was read. A specific person acted. State what evidence each claim needs.
6. **Later recall (next day, 5 minutes):** write the linking rule without the reference. Explain what a missing record can and cannot prove when logs have gaps.

For each pass, record your decision and reason. Cite the evidence. State what is unclear, any help used and one next check. If you can, ask someone to review your words and a new case. Until then, your skill at doing this alone is unassessed, even if all labels match. Keep all attempts below `run/`.
