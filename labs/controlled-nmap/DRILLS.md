# Practice sequence

You may use the README Answer vocabulary on every first attempt. It gives exact label spellings but does not match them to a case. Keep reference answers and `analyse` closed until you save your prediction.

1. **Guided:** predict all three inventory rows before opening the worked example. Circle the evidence that supports each service label.
2. **Prompts:** What does a port-name table know? What extra evidence does a probe add? Which local bind would accept a remote connection? What can a timeout hide?
3. **Challenge:** prepare `challenge` in `run/attempt-02`. Do not open answers or `analyse`. Make a list of the ports and services. For each unclear row, name one small next check.
4. **Changed:** prepare `changed` in another new folder. Compare local and remote evidence. If they disagree, give two possible reasons. Name the evidence needed to choose between them.
5. **Personal tool session:** follow the README on the owned isolated pair only. Keep scope, first scan, actual command/version, listener snapshots and cleanup evidence. Compare with the worksheet without replacing either.
6. **Teach-back:** use a door number to explain a port to someone new. Explain where that comparison helps and where it stops.
7. **Later recall:** two days later, write the scope and cleanup checks from memory. Reopen the README and record corrections. Do not rerun a scan from memory without checking scope.

Handover includes the first attempt, help used and rows still unclear. A matching label does not show that you ran Nmap. It does not prove that you can do the task on your own.
