# Practice stages

1. Guided: prepare `guided`, write the prediction first, then run it. Keep
   the first notes and compare with WORKED-EXAMPLE.md only afterwards.
2. Prompts: Is the text "2" the same JSON type as 2? Can JSON that parses still break the order rules?
3. Independent: Use `challenge`. Predict which stage checks each request first. Save the table before you run it or read its reference.
4. Changed: Use `changed`. Find the limits for text length, byte size and value type. In a new copy test count 1, count 0, and one ordinary Unicode name.
5. Teach-back: Explain why a request that breaks the rules should get a useful error. Why should it not reveal a traceback, which lists the code path to a failure?
6. Later recall: next week, use a new attempt folder. Keep the source closed. Predict one limit, one type error and one valid order. Then check your reasons.

Label notes `first attempt`, `revised after evidence` or `later recall`.
These labels show the stage. They do not prove skill. Keep what you saw
apart from what you first thought would happen. Ask someone to review your
reasons and what you still need to check.
