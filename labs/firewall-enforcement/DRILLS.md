# Practice sequence

You may use the README Answer vocabulary on every first attempt. It gives exact label spellings but does not match them to a case. Keep reference answers and `analyse` closed until you save your prediction.

1. **Guided:** prepare guided. Predict both connection labels and rollback, then open the worked example. Mark each field that supports your choice in a before/during/after table.
2. **Prompts:** Could stopping the service also make a connection fail? Why keep the allowed control? Does a packet counter count connections? Why verify rollback before stopping listeners?
3. **Challenge:** prepare challenge in a fresh run folder. Keep reference answers closed. Decide which claims the evidence supports and save two next checks.
4. **Changed:** prepare changed in a new folder. Compare the intended rule result with what you see. Save your first view before you revise it.
5. **Personal VM session:** follow the README only on the stated disposable setup. Save the baseline and timer state. Keep the allowed/denied test results, counter/log evidence and restored state. Mark any step you did not run.
6. **Teach-back:** explain to someone new to networking why a test needs both a door that should open and a door that should stay shut.
7. **Later recall:** two days later, write the order of rollback checks from memory. Compare it with the README. Record corrections and help used. Do not change a firewall from memory.

Handover: give a reviewer the matrix and original evidence. Ask them which claims you saw and which causes you assumed. A finished worksheet does not assess your skill with a real firewall.
