# Practice sequence

1. **Guided:** prepare guided and draw before/after route arrows. Save the chosen prefix for each destination. Build the DNS table on its own before opening the worked example.
2. **Prompts:** Which is compared first, prefix length or metric? Can an IPv4 route cover IPv6? Can a tunnel default still leave a specific exception? Does routing an application destination decide its DNS path?
3. **Challenge:** prepare challenge in a fresh folder. Keep answers closed. Work through the route and DNS choices. Compare each result with the stated goal.
4. **Changed:** prepare changed in a new folder. Explain which routes are chosen and what still needs checking. Do not call every local path a leak. First check the user's intended scope.
5. **Small edit:** copy a prepared case. Change one DNS suffix or route prefix. Predict which rows will change, then compare. Keep the original and first prediction. A chosen route does not prove that a live connection worked.
6. **Teach-back:** use the bus-and-directions example to explain the two choices. Then explain why resolvers tied to network links need evidence beyond this model.
7. **Later recall:** two days later, write the prefix/metric and suffix choice orders without notes. Check them. Record corrections, help used and points still unclear.

Handover includes route maps, DNS paths and a small plan to check them. Keep any optional VM evidence separate. The supplied exercise does not show a live VPN connection. It does not prove that you can do the task on your own.
