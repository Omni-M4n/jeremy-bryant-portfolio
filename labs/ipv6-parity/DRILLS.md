# Practice sequence

You may use the README Answer vocabulary on every first attempt. It gives exact label spellings but does not match them to a case. Keep reference answers and `analyse` closed until you save your prediction.

1. **Guided:** prepare guided, draw both address paths and fill the matrix before using the worked example.
2. **Prompts:** Does a failed connection prove a rule worked? Does an inet table mean every rule covers both families? Does a shared socket prove both paths are reachable?
3. **Challenge:** prepare challenge into a fresh folder. Keep answers closed. Save your current view and the smallest next check that could improve it.
4. **Changed:** prepare changed in a new folder. Compare causes as well as success/failure. Draw the paths you would propose after reviewing the case. Do not make live changes.
5. **Optional personal evidence:** use only the prepared isolated pair described in the README. Keep both probe outputs and mark every missing step. The made-up case does not show that you ran these tests.
6. **Teach-back:** explain why two failed entrances need not have the same cause. Point to the evidence for each arrow on your diagram.
7. **Later recall:** two days later, write the table headings without notes. Check them. Record corrections, help used and evidence still missing or unclear.

Handover: keep the first attempt, diagram and test plan. A matching answer does not prove that you can do the task on your own. It does not prove that the whole network is safe.
