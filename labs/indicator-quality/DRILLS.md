# Indicator-review practice ladder

Use a new `run/attempt-NN` folder for each stage. Record the date, Python
version, case ID, first prediction, evidence references, review-date arithmetic,
help used and correction. Save the worksheet before `check`; it reveals expected
labels where yours differ. A matching label is package feedback, not an
assessment.

Use only this exact vocabulary: `review-expiry`, `review-conflict`,
`seek-support`, `narrow-scope`, `retain-as-context`.

## Guided practice — attempt 01, 15-20 minutes

Prepare `guided`. Read the README and fill one row per record with value/type,
evidence ID, all four relevant times, supplied conflict, source, stated
confidence, scope, decision and review date. Apply the precedence in order.
Save the first answer before opening `WORKED-EXAMPLE.md`. Keep the original and
write any correction beside it.

## Changed case — attempt 02, 10-15 minutes

Prepare `changed` before the challenge. Close the worked example and past
answers. Test expiry before considering the supplied conflict flag. For each
decision, say which later rule would otherwise have applied and why precedence
stopped there. Show the comparison with `as_of` exactly, save the first answer,
then check it. Do not overwrite attempt 01.

## Solo rehearsal — shipped challenge attempt 03, 15-20 minutes

Prepare the shipped `challenge` in a new folder. This is a solo rehearsal using
a known package fixture; it is not a fresh unseen case, not reviewer-provided and
not independently assessed. Keep the worked example, references, tests and past
answers closed. Use only the supplied case and README rules. Record every field,
choose only the exact vocabulary above and save before checking. Ask a person to
review the field references, limits and next request afterward.

## Teach-back — 5 minutes

Explain why a copied label or confidence 69 reaches `seek-support`, confidence
70 does not, a shared-service record reaches `narrow-scope`, and an otherwise
eligible record reaches `retain-as-context`. Then explain why expiry and conflict
take precedence. Say why none of those labels establishes truth, reliability,
malice, attribution or permission to block.

Use this exact handover prompt:

> Which supplied fields determined the decision and review date, what do those
> fields not verify, and what smallest support would you request next?

## Later recall — 10 minutes

On another day, write the five rules and review-date rule from memory before
opening the README. Use a fresh practice copy, change one valid field and predict
the result. Keep the case synthetic and offline. Retain the first answer, actual
result and correction. If a reviewer creates different facts, record that help
and ask them to assess the reasoning; the package checker cannot do so.
