# Practice and recall

1. Guided: predict all three operations, then read the worked example. Keep your
   original answers and mark what changed in a second note.
2. With prompts: copy the prepared case to a new run folder. Add only a file
   `write` allow rule for `reader` before inherited rules. Which request changes?
3. Independent: prepare `challenge`. Keep references closed. Trace each request
   through both objects where needed. Cite the first rule that settles each route.
4. Changed case: prepare `changed`. Explain the order of explicit and inherited
   rules. Change the explicit grant's trustee to `visitor` in your run copy.
   Predict again before checking.
5. VM evidence: follow the README on a new VM. Record a success and a denial from
   the dummy account. Keep unexpected results and explain the next check.
6. Teach back: use a door key and room key example to explain why the parent can
   supply another deletion route. Then state where that analogy stops working.
7. Later recall: two days later, without notes, list the four rule-order groups.
   Explain why a screenshot of an ACL is weaker evidence than an operation test.

Handover: first attempt, changed answer, operation transcript, limits, help used,
and the next unfamiliar action you would test. A reviewer checks reasoning.
