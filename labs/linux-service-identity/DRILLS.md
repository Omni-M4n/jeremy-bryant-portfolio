# Practice and recall

1. Guided: trace the service account and both commands. Then read the example.
2. With prompts: in a fresh run copy, change `q1` to target `root`. Keep the rule
   fixed. Which field now matters?
3. Independent: prepare `challenge`; keep the reference closed. Explain the
   process evidence first. Then explain the sudo rule evidence.
4. Changed case: prepare `changed`. Read each field and predict the labels.
   Does a match prove that the account has only the rights the job needs?
5. VM practice: run the harmless identity commands in the README. Save both
   results. Inspect all policy if a command works when you thought it would be denied.
6. Teach back: explain why `id -u` and `id -un` are separate requests even though
   they start with the same program name.
7. Later recall: in two days, list the three fields needed for an exact sudo rule
   match. Why might a service stop even when its account was set up as planned?
