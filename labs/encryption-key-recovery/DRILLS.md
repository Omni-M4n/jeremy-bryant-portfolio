# Practice sequence

1. **Guided, 30 minutes.** Prepare `guided`, identify exact source bytes and
   predict each decision. Save the worksheet before opening the worked example.
   Record what the helper actually computes and what it merely reads from a
   fictional receipt. Preserve the first attempt and corrections.
2. **Prompted.** For each sample ask whether the goal is representation,
   confidentiality or comparison. For each backup draw the dependency chain
   from stored object through the exact key and permission to checked output.
   Attach a ledger reference to each claim.
3. **Independent, 20-30 minutes.** Prepare `challenge` in `run/independent-01`.
   Close references, worked example and `analyse`. Explain every decision and
   choose one next check for each unresolved claim. Save before running `check`.
   A terse receipt must not become a broader conclusion without evidence.
4. **Changed case, 20 minutes.** Prepare `changed` in `run/changed-01`. Track
   byte boundaries and object-to-key dependencies. Write a dummy recovery plan
   that explicitly separates observed arrangements from unverified ones. Use no
   real key or account.
5. **Boundary experiment.** In a fresh attempt copy, compare no restored text
   (`null`) with an actual empty string (`""`). Then edit one source newline.
   Predict before analysis. Try a malformed Base64 string and record how input
   rejection differs from a valid encoding of different bytes. Keep fixtures
   unchanged and update readable companion notes for edited experiments.
6. **Teach-back.** Explain to a reviewer why a correct digest, a ciphertext copy,
   a key identifier and a success receipt answer different questions. Ask them
   to challenge one overbroad claim and preserve the correction.
7. **Recall.** Tomorrow reconstruct the comparison and dependency rules without
   notes. In about a week have a reviewer change one permission, key state or
   supplied content in a fresh valid case; repeat with solutions closed.

Record stage, date, input, evidence, help and corrections. Passing helper checks
does not replace a personally performed, separately authorised encryption-tool
exercise or an assessed explanation of an unfamiliar case.
