Study note / Recovery testing

A backup is not yet a restore.

A local dummy-data exercise about completeness, recovered versions and the limits of a successful copy command.

19 November 2026 · Personal lab · Synthetic files only

The observed result

The operation completed. One expected file did not return.

I ran a small local restore drill with two expected files. The restore operation completed, but only one file came back.

The scenario used disposable dummy data. I recorded the original two-file inventory, created a deliberately incomplete backup, and then changed the current version of one file. The backup was restored into a new folder rather than over the working data.

The receipt showed three useful results: item-01.txt returned in its older baseline version, item-02.txt was missing, and no unexpected files appeared in the restored folder. The mechanism copied what the backup contained, but the recovered set did not meet the required inventory.

A repeatable check

Test the recovery, not only the backup job.

  1. Record the complete expected inventory.
  2. Restore into a separate, empty location.
  3. Compare every expected file with the restored set.
  4. Report missing and unexpected files independently.
  5. Confirm which saved version was recovered.
  6. Measure copying and verification separately.
  7. Assess completeness, version age and the time target as separate requirements.

The local receipt recorded copy and verification durations independently. Those measurements describe this small operation; timings from two tiny files cannot establish disaster-recovery performance. They exclude application startup, permissions, infrastructure provisioning, key recovery, network transfer and operational coordination.

The practical takeaway is that a successful copy command answers only one question. Recovery confidence requires evidence that the expected data returned, the correct version was recovered and the result meets the needs defined before the test.

Sources and scope

Inspect the exercise and its planning basis.

  • Public restore-drill lab ↗README, synthetic scenarios, code, checks and stated limits.
  • NIST SP 800-34 Rev. 1 ↗Contingency-planning and recovery guidance.

This exercise establishes a bounded local dummy-data result. It does not demonstrate application, operating-system, cloud or full-machine recovery.
