02 How I approach a problem

Curiosity is
the starting point.
Evidence is the next.

I’m studying cybersecurity at Deakin University and developing my skills through practical projects and technical writing.

I enjoy understanding how a system fits together: what it exposes, what a change affects, and how to tell whether it actually worked. My portfolio follows that process, including the parts that needed another attempt.

These are learning projects. I document the help I use, credit community developers and distinguish tested results from work still in progress.

More about my path ↗
01 / OBSERVE

Establish what is actually there.

Identify the device, software and network state before deciding what a result means. A page loading is an observation; administrator access needs separate evidence.

02 / CHANGE

Keep changes understandable.

Work in manageable steps. Preserve the previous configuration and understand the path back before making a change persistent.

03 / VERIFY

Check the outcome in real use.

Restart the device, try its normal functions and record the result. A successful command is only part of the story.
