01 / Web access controls

Access Notes

A private notes app with two fictional users. Sign in as each user, create a note and check that changing a note ID never grants access to someone else's work.

The question
How does a server decide which records a signed-in user may read or change?
The code
Python, Flask, Werkzeug password hashing and SQLite. SQL queries check both the note ID and its owner.
The checks
Cross-user access, request tokens, session expiry and logout, unsafe input, and escaped note text.
The limit
A loopback learning app with fictional accounts. Wider deployment needs a separate review of HTTPS, identity, abuse controls and operations.

02 / Evidence and reporting

Scan Report

A small command-line tool that turns a supplied JSON findings file into an offline HTML report. It groups findings by severity, preserves confidence and evidence, and gives a reviewer a clear next step.

The question
How can untrusted scan results become a useful report without hiding missing evidence or running supplied markup?
The code
Python's standard library. Read a file, validate each finding, sort the results, escape text and write a report.
The checks
Malformed input, file limits, script-like text, stable output and preserving existing files.
The limit
The input uses a documented, small JSON format. A scanner observation still needs review and a retest before a claim is confirmed.

Learn one path at a time

  1. Run the supplied example and explain what you see.
  2. Trace one request or finding through the code.
  3. Make one small change and run the related test.
  4. Fix a fault in a fresh copy.
  5. Give a short demonstration, then answer questions without the guide.

Use each project's practice file to record what you can do with notes and what you can do on your own. These programs extend the existing access-control and finding-report labs.
